# Glossary

Canonical domain terminology for the Enterprise IT Support Agentic RAG system.

## Domain Concepts

### Agentic RAG
A self-corrective Retrieval-Augmented Generation architecture powered by LangGraph that dynamically routes user inquiries, retrieves private enterprise knowledge from Pinecone vector databases, grades retrieval evidence, rewrites queries when ambiguous, falls back to external web search via Tavily when private evidence is weak, and generates grounded IT support responses.

### Workflow Backend
The execution persona selected per request, determining which classifier adapter drives decision routing and evidence grading:
- `fix_single_llm`: Canonical SelfCorrectiveRagWorkflow registered in WorkflowRegistry relying on OpenAI structured outputs (`deepseek-v4-flash`) via `OpenAIClassifierAdapter`.
- `fix_single_jev`: Canonical SelfCorrectiveRagWorkflow registered in WorkflowRegistry utilizing TypeSafe Classifier (`typesafe/jev-1.13`) via `JevClassifierAdapter` for deterministic categorical decisions and custom token telemetry.
- `react_agent`: Canonical ReActAgentWorkflow registered in WorkflowRegistry providing multi-turn autonomous tool-calling.

### Workflow Engine
The unified, stateless LangGraph topology factory (`app/rag/engine.py`) that constructs the 10-node self-corrective RAG lifecycle (routing, retrieval, grading, query rewriting, and generation). Exposes a pure factory interface (`create_agentic_rag_graph`) with explicit dependency injection for chat models (`model`) and tools (`kb_tool`, `web_tool`), free from mutable module globals or vestigial synchronous wrappers.

### Workflow Classifier (Classifier Seam)
A strongly-typed decision protocol (`app/rag/classifiers.py`) defining discrete methods (`route`, `grade_kb`, `grade_web`) required by the Workflow Engine to make routing and evidence sufficiency decisions.

### Classifier Adapter
A concrete adapter satisfying the `WorkflowClassifier` seam:
- `OpenAIClassifierAdapter`: Satisfies the seam using Pydantic JSON mode structured outputs.
- `JevClassifierAdapter`: Satisfies the seam using TypeSafe Classifier SDK while encapsulating token estimation and Langfuse span creation.

### Trace & Reasoning Steps
The sequence of discrete LangGraph nodes traversed during query resolution (e.g., `retrieve` -> `grade_evidence` -> `generate`). Serialized in chat responses as `trace: list[str]`.

### Trace ID
The unique identifier generated by the Langfuse observability SDK corresponding to a specific execution run. Embedded in API responses, local audit logs, and frontend telemetry accordions for end-to-end debugging and evaluation.

### Source Used
The originating evidence source attributed to the final answer:
- `vectorstore`: Answer generated solely from enterprise private documents stored in Pinecone.
- `web_search`: Answer generated from live external web search via Tavily after private knowledge proved insufficient or absent.
- `react_agent`: Answer generated through autonomous tool-calling iterations by ReActAgentWorkflow.
- `direct`: Answer formulated directly by the LLM without external evidence retrieval.

### Session Lifecycle
Multi-turn conversational tracking correlating user messages under a UUID v4 `session_id`. Persisted in client `localStorage` and propagated through `POST /api/chat` to tie sequential turns together in Langfuse traces and server context variables.

### Feedback Score
A normalized rating float between `0.0` (Thumbs Down / Poor) and `1.0` (Thumbs Up / Helpful) submitted via `POST /api/feedback` to evaluate response quality directly in Langfuse.

### Workflow Definition
A strongly-typed protocol (`app/rag/workflows/base.py`) defining the lifecycle contract for arbitrary workflow topologies. Encapsulates metadata (`WorkflowInfo`), compiled graph caching, state conversion adapters, streaming node whitelists, and error fallbacks.

### Workflow Registry
The central thread-safe registry (`app/rag/workflows/registry.py`) managing workflow lifecycles, lazy singleton graph compilation, and dynamic workflow lookup across HTTP and streaming routes.

### State Adapter
Bidirectional mapping methods (`to_initial_state` and `to_chat_response`) on `WorkflowDefinition` that convert between transport-level API schemas (`ChatRequest`, `ChatResponse`) and workflow-private graph states (e.g. `AgentState` or LangGraph message lists).

### Tool Abstraction Layer
The standardized collection of LangChain `BaseTool` implementations (`app/rag/tools/`) providing typed Pydantic input schemas, native asynchronous (`ainvoke`) execution, and dual-output (`content_and_artifact`) contracts consumable identically by fixed DAG nodes and autonomous ReAct agents.
_Avoid_: Helper functions, search clients, ad-hoc retrievers

### RAG Tool
A deep tool class (`RAGTool`) subtyping LangChain's `StructuredTool`, exposing first-class `execute` and `aexecute` entrypoints returning strongly-typed `ToolResult` containers for direct workflow DAG callers, while maintaining standard LangChain `invoke`/`ainvoke` contracts for autonomous ReAct agents. Injects `RunnableConfig` natively without global context variables.
_Avoid_: DualOutputStructuredTool, generic tool wrapper, tool helper

### Tool Evidence Artifact (Tool Artifact)
A strongly-typed domain model (`ToolEvidenceArtifact`) returned alongside human-readable tool prose in `response_format="content_and_artifact"`, encapsulating normalized `citations: list[Citation]`, `retrieved_contexts: list[str]`, `source_used: str`, and optional `raw_payload: Any` for direct consumption by workflow state nodes, autonomous agents, and evaluation listeners without string re-parsing or regex scraping.
_Avoid_: Raw tool output, metadata dictionary, heterogeneous artifact dict

### Tool Result
A strongly-typed container (`ToolResult`) returned by the tool execution seam (`execute_tool` / `aexecute_tool`) for direct workflow DAG callers, encapsulating `content: str` and `artifact: ToolEvidenceArtifact`. Eliminates tuple duck-typing and message unwrapping at tool invocation sites.
_Avoid_: Tool tuple, raw tool output, unpack helper

### Aggregated Tool Evidence
An immutable domain value object (`AggregatedEvidence`) produced by `aggregate_tool_evidence` in `app/rag/tools/`, encapsulating deduplicated `citations: list[Citation]`, ordered `retrieved_contexts: list[str]`, and dynamically resolved `source_used: str` across one or many executed tools, decoupling workflows and evaluation listeners from specific tool names.
_Avoid_: Extracted evidence tuple, workflow evidence helper, citation map

### Citation
The canonical, immutable domain value object (`Citation` in `app/rag/state.py`) representing a verifiable source attributed to retrieved evidence, encapsulating `title: str`, `url: str`, and `type: str` (e.g. `private_kb`, `web`). Preserved strictly as typed model instances across tool artifacts, workflow state, conversation memory turns, and presentation transport schemas without intermediate dictionary degradation.
_Avoid_: Citation dict, raw link tuple, citation dict shim

### Evaluation Context
A normalized data structure (`EvalContext`) extracted from arbitrary workflow states containing `source_used` and `retrieved_contexts`, enabling online evaluation tasks to grade answers across diverse topologies without assuming fixed vectorstore structures.

### Evaluation Engine (Evaluator Seam)
The unified evaluation subsystem (`app/rag/evaluation/`) encapsulating judge model lifecycles, test case synthesis, and metric scoring (e.g. faithfulness, answer relevancy) behind a cohesive protocol seam (`Evaluator`). Serves both online background telemetry and offline benchmark experiments without leaking internal state.
_Avoid_: Ad-hoc scoring script, judge singleton, eval helper

### Thread ID (Checkpointer Lifecycle)
The LangGraph configuration key (`configurable: {"thread_id": session_id}`) tying stateful, multi-turn conversational agents to durable in-memory (`MemorySaver`) or external checkpointer storage.

### Knowledge Store (Storage Seam)
A strongly-typed protocol seam (`VectorStoreAdapter`) defining the storage and similarity retrieval contract for enterprise documents. Decouples vector persistence from concrete database vendors.

### Vector Store Adapter
A concrete adapter satisfying the `VectorStoreAdapter` storage seam:
- `PineconeVectorStoreAdapter`: Production implementation connecting to Pinecone Serverless.
- `InMemoryVectorStoreAdapter`: In-memory implementation providing deterministic similarity search without network dependencies for fast unit testing.

### Document Indexer
The deep write-path module (`app/rag/knowledge/indexer.py`) coordinating document loading, chunking strategy dispatch, embedding generation, batch scheduling, and vector persistence behind a high-leverage entrypoint (`index_file`, `index_batch`).
_Avoid_: Ingestion helper, upload processor, ad-hoc batch loader

### Document Parser
A pluggable strategy protocol (`DocumentParser`) responsible for reading a raw file path and returning a normalized list of LangChain `Document` objects based on supported file formats.

### Document Chunker
A pluggable strategy protocol (`DocumentChunker`) partitioning parsed documents into retrieval-optimized text segments with preserved metadata and configurable overlap.

### Workflow Runner
The deep execution and streaming runtime module (`app/rag/workflows/runner.py`) orchestrating workflow invocation, LangGraph `astream_events` polling, selective token delta filtering, telemetry context binding, trace normalization, and unified listener lifecycle dispatch behind a compact execution interface (`execute`, `aexecute`, and `stream`), completely decoupled from wire transport protocols and lifecycle side-effects.
_Avoid_: Event generator, stream helper, route executor

### Workflow Execution Event
A strongly-typed, self-contained domain model (`WorkflowExecutionEvent`) emitted during workflow streaming, encapsulating discrete execution milestones (`StepTransitionEvent`, `TokenDeltaEvent`, `ExecutionCompletedEvent`, `ExecutionFailedEvent`) independent of transport wire serialization or client communication protocols. `StepTransitionEvent` carries its own canonical node identifier (`step`), human-readable progression label (`label`), and chronological milestone (`timestamp`), eliminating presentation-layer event hydration.
_Avoid_: SSE chunk, stream string, raw delta dictionary

### Stream Transport Adapter
A presentation adapter (`SseStreamAdapter`) translating self-contained domain execution event streams into transport-specific wire protocols (such as Server-Sent Events or WebSockets) for network delivery without requiring external lookup dictionaries or workflow introspection.
_Avoid_: Stream serializer, SSE helper, socket bridge

### Execution Lifecycle Listener
A pluggable event-driven listener protocol (`ExecutionLifecycleListener`) decoupling post-execution side-effects (such as conversation memory persistence and online evaluation scoring) uniformly across all execution modes (`execute`, `aexecute`, and `stream`) from the core workflow execution engine.
_Avoid_: Post-execution hook, background task helper, runner callback

### Conversation Memory (Memory Seam)
A strongly-typed protocol seam (`ConversationMemoryAdapter`) defining the storage, retrieval, truncation, and branching lifecycle for multi-turn conversational history. Decouples conversation persistence from graph checkpointer internals and concrete database engines.
_Avoid_: Session dict, LangGraph checkpointer, global memory, chat cache

### Conversation Memory Adapter
A concrete adapter satisfying the `ConversationMemoryAdapter` storage seam:
- `SQLiteConversationStore`: Production and development persistent store maintaining chat sessions and rich turn history across server restarts using standard library `sqlite3` in WAL mode.
- `InMemoryConversationStore`: Fast, isolated in-memory store for deterministic unit testing (`pytest`) and ephemeral executions.
- `NoOpMemoryStore`: Stateless pass-through store when conversation memory is explicitly disabled.

### Conversation Session
A strongly-typed domain aggregate model (`ConversationSession`) subtyping `SessionInfo`, encapsulating both the session metadata (`session_id`, `title`, `parent_session_id`, `forked_from_turn`, `created_at`, `updated_at`, `turn_count`) and its chronological sequence of `turns: list[ConversationTurn]`. Eliminates caller-side assembly of disjointed session entities.
_Avoid_: Session tuple, raw session dictionary, fragmented session payload

### Conversation Turn
A strongly-typed domain model (`ConversationTurn`) representing a single completed conversational exchange within a session, encapsulating `session_id`, 0-based `turn_index`, `user_query`, `assistant_answer`, `attachments`, `citations`, `source_used`, `trace_id`, and `created_at`. Strictly excludes intermediate tool scratchpads.

### In-Place Turn Rewind (Truncation)
The conversational capability allowing a user to edit past query $k$ and continue execution within the existing session, safely pruning all turns $\ge k$ from persistent storage atomically upon successful turn completion via `aappend_turn(..., rewind_turn_index=k)`, or explicitly via `atruncate_from` for standalone rewind endpoints.

### Atomic Turn Append
The deep entrypoint (`aappend_turn`) on `ConversationMemoryAdapter` that atomically calculates the monotonic `turn_index`, commits in-place rewind truncation (if rewinding), persists the new completed `ConversationTurn`, and updates session timestamps within a single database transaction.
_Avoid_: Manual turn counting, separate truncate-then-save calls, caller-managed indexing

### Conversation Branching (Forking)
The capability (`afork_session`) to clone conversation turns $[0 \dots k]$ into a new child session (`new_session_id`) with lineage metadata (`parent_session_id`, `forked_from_turn`) returning the complete `ConversationSession` aggregate atomically, enabling alternative exploration branches without modifying the original session or issuing subsequent read queries.
_Avoid_: String session ID return, manual fork hydration, multi-step branching query

### Query Condensation (Contextualization)
A fast pre-retrieval graph step (`condense_query`) in multi-turn workflows that resolves pronouns and ambiguous references against prior conversational turns (`messages[:-1]`) into a standalone retrieval query (`current_query`) before vector store or web search dispatch.
_Avoid_: Query rewrite, prompt stuffing, raw query search

### Prompt Store (Prompt Seam)
A strongly-typed protocol seam (`PromptStore`) defining the template resolution, compilation, and telemetry observation binding lifecycle for all system prompts. Decouples LLM callers and decision classifiers from concrete CMS backends and external observability SDKs.
_Avoid_: Prompt helper, prompt CMS singleton, raw template dictionary

### Prompt Store Adapter
A concrete adapter satisfying the `PromptStore` seam:
- `LangfusePromptStore`: Production adapter retrieving managed templates from Langfuse Prompt CMS with in-memory TTL caching, automatic fail-open local fallback, and Langfuse observation linking.
- `LocalPromptStore`: Fast, isolated in-memory adapter backed by canonical local template strings for deterministic unit testing (`pytest`) and offline execution.

### Rendered Prompt
A strongly-typed domain model (`RenderedPrompt`) produced by `PromptStore.render`, encapsulating the compiled prompt text (`text`), pre-merged execution configuration with trace and observation metadata (`config`), and the underlying provider prompt reference (`raw_prompt`).
_Avoid_: Formatted prompt string, prompt tuple, template dict

### Execution Context Binder
The deep execution preparation module (`app/rag/workflows/binder.py`) orchestrating 3-tier parameter precedence resolution, telemetry tag composition, read-path conversational memory hydration, and state normalization behind a compact `bind`/`abind` interface, decoupling execution configuration from LangGraph runtime loops.
_Avoid_: Runner helper, prep handler, parameter manager

### Bound Execution Context
An immutable domain value object (`BoundExecutionContext`) produced by `ExecutionContextBinder`, encapsulating the resolved workflow definition, initial graph state, pre-merged runnable configuration with callbacks, and telemetry identifiers ready for immediate graph invocation.
_Avoid_: Prep tuple, runner context dict, execution config dictionary

### Workflow Step (Step Seam)
A strongly-typed protocol seam (`WorkflowStep` in `app/rag/steps/base.py`) defining the execution contract for individual graph nodes. Step instances encapsulate their own injected dependencies (models, tools, prompt stores, classifiers), define `inputs` / `outputs` blackboard key mappings, and are directly callable (`async def __call__` delegating to `async def execute(self, state, config) -> dict[str, Any]`), enabling plug-and-play assembly into LangGraph topologies without nested wrapper closures.
_Avoid_: Node closure, graph helper, inline step lambda

### Step Catalog
The central thread-safe registry (`StepCatalog` in `app/rag/steps/base.py`) managing built-in and dynamically registered step types, exposing the `@register_step("alias")` decorator and supporting dotted Python path fallbacks (`"module.path:StepClass"`) for bespoke execution logic.
_Avoid_: Step map, node dictionary, ad-hoc step loader

### Workflow Compiler
The declarative topology compiler (`WorkflowCompiler` in `app/rag/workflows/compiler.py`) that reads declarative workflow manifests (YAML / JSON) and compiles them into executable, registered `WorkflowDefinition` instances backed by LangGraph topologies, wiring step instances, isolated tool scopes, and conditional edges automatically.
_Avoid_: YAML loader, graph builder helper, topology script

### Attachment
The canonical, strongly-typed domain value object (`Attachment` in `app/rag/state.py`) representing multimodal and structured payloads (images, PDFs, audio, structured data files), encapsulating `id: str`, `mime_type: str`, `url: str | None`, `content_bytes: bytes | None`, and `metadata: Mapping[str, Any]` (recursively frozen and read-only). Preserved across API transport schemas, conversational memory turns, and LangChain message content blocks.
_Avoid_: Attachment dict, raw file tuple, untyped payload dictionary

### Agent Handoff
A first-class routing mechanism and declarative YAML primitive enabling an autonomous agent step to transfer conversational execution to another specialized agent or supervisor, synthesized by the `WorkflowCompiler` into dynamic transfer tools and LangGraph conditional edges.
_Avoid_: Sub-agent jump, tool redirect, ad-hoc router function
