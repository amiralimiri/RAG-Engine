# Glossary

Canonical domain terminology for the Enterprise IT Support Agentic RAG system.

## Domain Concepts

### Agentic RAG
A self-corrective Retrieval-Augmented Generation architecture powered by LangGraph that dynamically routes user inquiries, retrieves private enterprise knowledge from Pinecone vector databases, grades retrieval evidence, rewrites queries when ambiguous, falls back to external web search via Tavily when private evidence is weak, and generates grounded IT support responses.

### Workflow Backend
The execution persona selected per request, determining which classifier adapter drives decision routing and evidence grading:
- `fix_single_llm`: Relies on standard OpenAI structured outputs (`deepseek-v4-flash`) via `OpenAIClassifierAdapter`.
- `fix_single_jev`: Utilizes TypeSafe Classifier (`typesafe/jev-1.13`) via `JevClassifierAdapter` for deterministic categorical decisions and custom token telemetry.

### Workflow Engine
The unified, deep LangGraph execution pipeline (`app/rag/engine.py`) that orchestrates the self-corrective RAG lifecycle (routing, retrieval, grading, query rewriting, and generation). Exposes a small interface (`ask` and `create_agentic_rag_graph`) while hiding state transitions, citation formatting, and streaming token dispatch.

### Workflow Classifier (Classifier Seam)
A strongly-typed decision protocol (`app/rag/classifiers.py`) defining discrete methods (`route`, `grade_kb`, `grade_web`) required by the Workflow Engine to make routing and evidence sufficiency decisions.

### Classifier Adapter
A concrete adapter satisfying the `WorkflowClassifier` seam:
- `OpenAIClassifierAdapter`: Satisfies the seam using Pydantic JSON mode structured outputs.
- `JevClassifierAdapter`: Satisfies the seam using TypeSafe Classifier SDK while encapsulating token estimation and Langfuse span creation.

### Trace & Reasoning Steps
The sequence of discrete LangGraph nodes traversed during query resolution (e.g., `retrieve` -> `grade_evidence` -> `generate`). Serialized in chat responses as `trace: list[str]`.

### Trace ID
The unique identifier generated by the Langfuse observability SDK corresponding to a specific execution run. Embedded in API responses, local audit logs, and frontend telemetry accordions for end-to-end debugging and evaluation.

### Source Used
The originating evidence source attributed to the final answer:
- `vectorstore`: Answer generated solely from enterprise private documents stored in Pinecone.
- `web_search`: Answer generated from live external web search via Tavily after private knowledge proved insufficient or absent.
- `react_agent`: Answer generated through autonomous tool-calling iterations by ReActAgentWorkflow.
- `direct`: Answer formulated directly by the LLM without external evidence retrieval.

### Session Lifecycle
Multi-turn conversational tracking correlating user messages under a UUID v4 `session_id`. Persisted in client `localStorage` and propagated through `POST /api/chat` to tie sequential turns together in Langfuse traces and server context variables.

### Feedback Score
A normalized rating float between `0.0` (Thumbs Down / Poor) and `1.0` (Thumbs Up / Helpful) submitted via `POST /api/feedback` to evaluate response quality directly in Langfuse.

### Workflow Definition
A strongly-typed protocol (`app/rag/workflows/base.py`) defining the lifecycle contract for arbitrary workflow topologies. Encapsulates metadata (`WorkflowInfo`), compiled graph caching, state conversion adapters, streaming node whitelists, and error fallbacks.

### Workflow Registry
The central thread-safe registry (`app/rag/workflows/registry.py`) managing workflow lifecycles, lazy singleton graph compilation, and dynamic workflow lookup across HTTP and streaming routes.

### State Adapter
Bidirectional mapping methods (`to_initial_state` and `to_chat_response`) on `WorkflowDefinition` that convert between transport-level API schemas (`ChatRequest`, `ChatResponse`) and workflow-private graph states (e.g. `AgentState` or LangGraph message lists).

### Tool Abstraction Layer
The standardized collection of LangChain `BaseTool` implementations (`app/rag/tools/`) providing typed Pydantic input schemas, native asynchronous (`ainvoke`) execution, and dual-output (`content_and_artifact`) contracts consumable identically by fixed DAG nodes and autonomous ReAct agents.
_Avoid_: Helper functions, search clients, ad-hoc retrievers

### Tool Artifact
The strongly-typed structured payload returned alongside human-readable tool prose in `response_format="content_and_artifact"`, encapsulating raw data (`list[Document]`, citations list, external URLs) for direct consumption by workflow state nodes without string re-parsing.
_Avoid_: Raw tool output, metadata dictionary

### Evaluation Context
A normalized data structure (`EvalContext`) extracted from arbitrary workflow states containing `source_used` and `retrieved_contexts`, enabling online evaluation tasks to grade answers across diverse topologies without assuming fixed vectorstore structures.

### Thread ID (Checkpointer Lifecycle)
The LangGraph configuration key (`configurable: {"thread_id": session_id}`) tying stateful, multi-turn conversational agents to durable in-memory (`MemorySaver`) or external checkpointer storage.
